# ০১.১। লিনাক্স ইউজার ম্যানেজমেন্ট ও SSH নিরাপত্তা

> **এই অধ্যায়ে যা শিখবেন:**  
> লিনাক্স একটি মাল্টি-ইউজার সিস্টেম। এই অধ্যায়ে আমরা ইউজারের প্রকারভেদ থেকে শুরু করে ইউজার তৈরি, কনফিগার, সুরক্ষা, পারমিশন, sudo, বিশেষ পারমিশন বিট, পাসওয়ার্ড এজিং এবং SSH অ্যাক্সেস নিয়ন্ত্রণ — সবকিছু ধাপে ধাপে হাতে-কলমে শিখবো।  
> **বিশেষ নোট:** এই অধ্যায়ে **Debian/Ubuntu** ডিস্ট্রিবিউশনের জন্য বিশেষ নির্দেশনা ও চেকলিস্ট অন্তর্ভুক্ত করা হয়েছে।

## ১. লিনাক্সে ইউজারের প্রকারভেদ

লিনাক্স একটি **মাল্টি-ইউজার** অপারেটিং সিস্টেম — একসাথে একাধিক ব্যবহারকারী কাজ করতে পারেন। প্রতিটি ইউজারকে সিস্টেম চেনে তার **UID** (User ID) দিয়ে, নাম দিয়ে নয়।

| ইউজার টাইপ               | UID   | বৈশিষ্ট্য                                             |
| ------------------------ | ----- | ----------------------------------------------------- |
| **রুট (Root/Superuser)** | 0     | সিস্টেমের অ্যাডমিন; আনলিমিটেড ক্ষমতা                  |
| **সিস্টেম ইউজার**        | 1-999 | সার্ভিস (Apache, MySQL, Nginx) চালানোর জন্য; লগইন নেই |
| **সাধারণ ইউজার**         | 1000+ | নিজের হোম ডিরেক্টরিতে সীমাবদ্ধ                        |

### সিস্টেম ইউজার তৈরি (Advanced)

সার্ভিস চালানোর জন্য ডেডিকেটেড সিস্টেম ইউজার তৈরি করা হয়:

```bash
sudo useradd -r nginx
```

- `-r` → সিস্টেম ইউজার (UID 1-999 রেঞ্জ থেকে)
- হোম ডিরেক্টরি তৈরি হয় না, লগইন করতে পারে না — যেটা নিরাপত্তার জন্যই কাঙ্ক্ষিত

### Root ইউজার এবং Normal ইউজারের মূল পার্থক্য

| বিষয়                  | Root ইউজার                                      | Normal ইউজার                                      |
| ---------------------- | ----------------------------------------------- | ------------------------------------------------- |
| ক্ষমতা                 | অসীম — যেকোনো ফাইল পরিবর্তন/ডিলিট করতে পারে     | সীমিত — শুধু নিজের হোম ডিরেক্টরির ফাইল অ্যাক্সেস |
| সিস্টেমের নিরাপত্তা    | একটি ভুল কমান্ড পুরো সিস্টেম ক্র্যাশ করতে পারে  | শুধু নিজস্ব ফাইলের ক্ষতি হয়, মূল সিস্টেম নিরাপদ  |
| UID                    | সবসময় 0                                        | সাধারণত 1000 বা তার ওপর থেকে শুরু                 |
| টার্মিনাল প্রম্পট     | `#` চিহ্ন                                       | `$` চিহ্ন                                         |
| সফটওয়্যার ইনস্টলেশন   | সরাসরি ইনস্টল/রিমুভ করতে পারে                   | sudo পারমিশন ছাড়া ইনস্টল করতে পারে না            |

### sudo কখন ব্যবহার করতে হয়

লিনাক্সে মূলত এমন সব কাজের আগে sudo ব্যবহার করতে হয়, যা সরাসরি পুরো সিস্টেমের নিরাপত্তা, কনফিগারেশন বা ফাইল স্ট্রাকচারকে প্রভাবিত করে। প্রধান ৫টি ক্যাটাগরি:

1. **সফটওয়্যার ইনস্টল বা আপডেট** — `sudo apt install`, `sudo dnf update`
2. **ইউজার ও গ্রুপ ম্যানেজমেন্ট** — `sudo useradd`, `sudo usermod`
3. **সিস্টেম ফাইল পরিবর্তন** — `/etc/` ডিরেক্টরির কনফিগ ফাইল এডিট
4. **সার্ভিস ও সিস্টেম কন্ট্রোল** — `sudo systemctl start nginx`, `sudo reboot`
5. **হার্ডওয়্যার ও ডিস্ক ম্যানেজমেন্ট** — `sudo fdisk`, `sudo mount`

## ২. গ্রুপ কী?

গ্রুপ হলো **অনেক ইউজারকে একসাথে ম্যানেজ করার ব্যবস্থা**। ৫০ জন ডেভেলপারের প্রত্যেককে আলাদাভাবে পারমিশন দেওয়ার বদলে একটা `developers` গ্রুপে রেখে একবারেই পারমিশন দেওয়া যায়।

দুই ধরনের গ্রুপ আছে:

| ধরন                 | বর্ণনা                                                                                             |
| ------------------- | -------------------------------------------------------------------------------------------------- |
| **Primary Group**   | ইউজার তৈরির সময় অটোমেটিক তার নামেই একটা গ্রুপ তৈরি হয় (যেমন: `sakil` ইউজারের জন্য `sakil` গ্রুপ) |
| **Secondary Group** | অতিরিক্ত পারমিশনের জন্য ইউজারকে অন্য গ্রুপে যুক্ত করা হয় (যেমন: `sudo`, `developers`)             |

### Primary vs Secondary গ্রুপের পার্থক্য

| বিষয়                | Primary Group                                      | Secondary Group                                      |
| -------------------- | -------------------------------------------------- | ---------------------------------------------------- |
| সংখ্যা               | একজন ইউজারের শুধুমাত্র একটিই থাকতে পারে            | একাধিক Secondary গ্রুপের সদস্য হতে পারে              |
| নতুন ফাইল তৈরি       | নতুন ফাইল/ফোল্ডার অটোমেটিক Primary গ্রুপের মালিকানায় যায় | সরাসরি কোনো ভূমিকা নেই                               |
| তৈরির সময়           | ইউজার তৈরির সাথে সাথেই অটো তৈরি হয়                | অ্যাডমিনকে ম্যানুয়ালি তৈরি করতে হয়                 |
| মূল উদ্দেশ্য         | লগইনের নূন্যতম অধিকার দেওয়া                       | নির্দিষ্ট ফোল্ডার/প্রজেক্টে ফাইল শেয়ার করা          |

## ৩. ইউজার ম্যানেজমেন্টের গুরুত্বপূর্ণ ফাইলসমূহ

লিনাক্সে সব ইউজার ও গ্রুপের তথ্য কিছু নির্দিষ্ট টেক্সট ফাইলে সংরক্ষিত থাকে। **কমান্ড চালালে আসলে এই ফাইলগুলোই পরোক্ষভাবে মডিফাই হয়** — তাই এগুলো বোঝা অপরিহার্য।

| ফাইল           | কাজ                                  | পারমিশন               |
| -------------- | ------------------------------------ | --------------------- |
| `/etc/passwd`  | ইউজারের নাম, UID, হোম ডিরেক্টরি, শেল | সবাই পড়তে পারে (644) |
| `/etc/shadow`  | এনক্রিপ্টেড পাসওয়ার্ড ও এজিং তথ্য   | শুধু root (000/400)   |
| `/etc/group`   | গ্রুপের তালিকা ও মেম্বার             | সবাই পড়তে পারে (644) |
| `/etc/gshadow` | গ্রুপের সুরক্ষিত পাসওয়ার্ড          | শুধু root             |

### ৩.১ `/etc/passwd` — ইউজার অ্যাকাউন্ট তথ্য

সবাই এই ফাইল **পড়তে পারে**, কিন্তু লিখতে পারে শুধু root। **৭টি ফিল্ড**, `:` দিয়ে আলাদা:

```text
root:x:0:0:root:/root:/bin/bash
daemon:x:2:2:daemon:/sbin:/sbin/nologin
```

| ফিল্ড | মান           | ব্যাখ্যা                                           |
| ----- | ------------- | -------------------------------------------------- |
| ১     | `rahim`       | ইউজারনেম (লগইন নাম)                                |
| ২     | `x`           | পাসওয়ার্ড placeholder (আসল হ্যাশ `/etc/shadow`-এ) |
| ৩     | `1001`        | UID (root=0, system=1-999, normal=1000+)           |
| ৪     | `1001`        | Primary গ্রুপের GID                                |
| ৫     | `Rahim Uddin` | GECOS (পুরো নাম/কমেন্ট)                            |
| ৬     | `/home/rahim` | হোম ডিরেক্টরি                                      |
| ৭     | `/bin/bash`   | শেল (`/sbin/nologin` = লগইন বন্ধ)                  |

### ৩.২ `/etc/shadow` — সুরক্ষিত পাসওয়ার্ড

শুধুমাত্র **root** পড়তে পারে। এখানে hashed পাসওয়ার্ড ও এজিং তথ্য সহ সর্বমোট ৯টি তথ্য থাকে:

```text
rahim:$6$K8x...:19700:5:90:7:14:19800:-
```

| ফিল্ড | মানে                                                            |
| ----- | --------------------------------------------------------------- |
| ১     | ইউজারনেম                                                        |
| ২     | এনক্রিপ্টেড পাসওয়ার্ড (`$6$`=SHA-512, `!`=লক, `*`=লগইন অসম্ভব) |
| ৩     | শেষ পরিবর্তন (১৯৭০ থেকে দিন গণনা)                               |
| ৪     | Min days — কমপক্ষে কতদিন পর বদলানো যাবে                         |
| ৫     | Max days — কতদিনের মধ্যে বদলাতেই হবে                            |
| ৬     | Warn days — মেয়াদ শেষের আগে সতর্কবার্তা                        |
| ৭     | Inactive — মেয়াদ শেষে লগইনের সুযোগ                             |
| ৮     | Expire — অ্যাকাউন্ট বন্ধের তারিখ                                |
| ৯     | সংরক্ষিত                                                        |

#### পাসওয়ার্ড ফিল্ডের অর্থ মনে রাখার ট্রিক

1. পাসওয়ার্ডে বড় টেক্সট থাকলে → **সক্রিয় অ্যাকাউন্ট**
2. পাসওয়ার্ডে `*` থাকলে → **লকড অ্যাকাউন্ট** (সিস্টেম ইউজার)
3. পাসওয়ার্ডে `!!` থাকলে → **পাসওয়ার্ড সেট করা নেই** (ডিজেবল্ড অ্যাকাউন্ট)

### ৩.৩ `/etc/group` — গ্রুপের তথ্য

```text
developers:x:1002:rahim,karim
```

| ফিল্ড         | বর্ণনা                                   |
| ------------- | ---------------------------------------- |
| 1. Group name | গ্রুপের নাম                              |
| 2. `x`        | পাসওয়ার্ড placeholder                   |
| 3. GID        | গ্রুপ ID                                 |
| 4. Members    | সেকেন্ডারি গ্রুপ মেম্বার (কমা-সেপারেটেড) |

> **নোট:** প্রাইমারি গ্রুপের মেম্বার এখানে দেখা যায় না — তা `/etc/passwd`-এর GID থেকে বোঝা যায়।

### ৩.৪ `/etc/gshadow` — গ্রুপের সুরক্ষিত তথ্য

```text
developers:!::rahim
```

`!` = গ্রুপ পাসওয়ার্ড নেই (ডিফল্ট)। গ্রুপ পাসওয়ার্ড থাকলে অন্য ইউজার `newgrp` দিয়ে গ্রুপে জয়েন করতে পারে।

### ফাইলগুলোর সম্পর্ক

```text
/etc/passwd  ←→  /etc/shadow   (ইউজার লিংক: username)
/etc/group   ←→  /etc/gshadow  (গ্রুপ লিংক: groupname)
```

### দরকারি কমান্ড

```bash
cat /etc/passwd                    # ফাইল দেখা
sudo cat /etc/shadow               # shadow দেখা (root লাগবে)
getent passwd rahim                # নির্দিষ্ট ইউজারের তথ্য
id rahim                           # UID, GID, গ্রুপ দেখা
pwck && grpck                      # ফাইলের ভুল যাচাই
ls -l /etc/passwd /etc/shadow      # পারমিশন দেখা
```

### নিরাপত্তা নোট

- `/etc/shadow` ও `/etc/gshadow` কঠোরভাবে root-সীমিত রাখুন — হ্যাশ লিক হলে **brute-force আক্রমণের ঝুঁকি** তৈরি হয়
- `/etc/passwd` ও `/etc/group` ম্যানুয়ালি এডিট **করবেন না** — এক ক্যারেক্টার ভুলে পুরো সিস্টেমে লগইন ভেঙে যেতে পারে

### ইউজার ডিফল্ট সেটিংস নিয়ন্ত্রণকারী ফাইল (Sysadmin Level)

```bash
/etc/default/useradd   # ডিফল্ট শেল, হোম ডিরেক্টরি লোকেশন
/etc/login.defs        # UID রেঞ্জ, পাসওয়ার্ড এজিং পলিসি
/etc/skel/             # নতুন ইউজারের হোমে যেসব ফাইল (.bashrc ইত্যাদি) যাবে
```

### ৩.৫ সিস্টেম ও ইউজার-ডিফাইন্ড ইউজার/গ্রুপ চেনার উপায়

CentOS 8 এবং আধুনিক লিনাক্স ডিস্ট্রিবিউশনগুলোতে আইডি সাধারণত এভাবে ভাগ করা থাকে:

| ইউজারের ধরণ            | UID / GID রেঞ্জ  | উদাহরণ                         |
| ---------------------- | ---------------- | ------------------------------ |
| Root (সুপার ইউজার)     | 0                | root                           |
| System Built-in        | 1 থেকে 999       | bin, daemon, mail, sshd, nginx |
| User-defined (Regular) | 1000 থেকে 60000+ | rony, asif, tisha              |

> **নোট:** পুরোনো লিনাক্স সিস্টেমে (যেমন CentOS 6) সিস্টেম ইউজারের রেঞ্জ ছিল ১ থেকে ৪৯৯ এবং রেগুলার ইউজার শুরু হতো ৫০০ থেকে।

#### শুধুমাত্র User-defined ইউজার দেখতে:

```bash
awk -F: '$3 >= 1000 && $3 != 65534 {print $1, $3}' /etc/passwd
```

#### শুধুমাত্র System Built-in ইউজার দেখতে:

```bash
awk -F: '$3 > 0 && $3 < 1000 {print $1, $3}' /etc/passwd
```

একইভাবে গ্রুপের জন্য `/etc/group` ফাইল ব্যবহার করুন। নির্দিষ্ট ইউজার চেক করতে:

```bash
id john    # uid=1001 হলে User-defined
id sssd    # uid=995 হলে System Built-in
```

## ৪. জরুরি কমান্ডসমূহ (Quick Reference)

### ইউজার তৈরি ও ডিলিট

```bash
sudo useradd username              # নতুন ইউজার (হোম ডিরেক্টরি হয় না!)
sudo passwd username               # পাসওয়ার্ড সেট

```

### ইউজার মডিফাই

```bash
sudo usermod -aG sudo rahim        # sudo গ্রুপে যোগ (Debian/Ubuntu)
sudo usermod -l newname oldname    # নাম পরিবর্তন (UID একই থাকে)
sudo usermod -s /bin/zsh rahim     # শেল পরিবর্তন
sudo usermod -d /home/newdir -m rahim  # হোম ডিরেক্টরি সরানো
```

### গ্রুপ ম্যানেজমেন্ট

```bash
sudo groupadd groupname            # গ্রুপ তৈরি
sudo groupdel groupname           # গ্রুপ ডিলিট
```

### ইউজার চেক

```bash
whoami                             # বর্তমান ইউজার
id username                        # UID, GID, গ্রুপ
groups username                    # গ্রুপ তালিকা
```

## ৫. ইউজার লাইফসাইকেল — ধাপে ধাপে ওয়াকথ্রু

এখন আমরা একটা ইউজারের **সম্পূর্ণ জীবনচক্র** হাতে-কলমে করবো:

> **তৈরি → কনফিগার → পরিবর্তন → সুরক্ষা → মুছে ফেলা**

### ধাপ ১: ইউজার তৈরি

**সাধারণ কমান্ড (অসম্পূর্ণ!):**

```bash
useradd sakil
```

**ভেতরে যা ঘটে:**
- ✅ `/etc/passwd` ও `/etc/shadow`-এ এন্ট্রি যোগ হয়
- ❌ হোম ডিরেক্টরি **তৈরি হয় না**
- ❌ ডিফল্ট শেল প্রায়ই `/bin/sh` (অসুবিধাজনক)

**সঠিক/প্রোডাকশন-রেডি উপায়:**

```bash
sudo useradd -m -s /bin/bash -c "Sakil Mahmud" sakil
```

| ফ্ল্যাগ        | কাজ                                            |
| -------------- | ---------------------------------------------- |
| `-m`           | `/home/sakil` হোম ডিরেক্টরি তৈরি (skel ফাইলসহ) |
| `-s /bin/bash` | শেল অ্যাসাইন                                   |
| `-c`           | GECOS ফিল্ডে পুরো নাম                          |

**ভেরিফাই:**

```bash
id sakil
# uid=1001(sakil) gid=1001(sakil) groups=1001(sakil)
```

### ধাপ ২: পাসওয়ার্ড সেট

নতুন ইউজার **লক অবস্থায়** থাকে — পাসওয়ার্ড সেট না করা পর্যন্ত লগইন অসম্ভব:

```bash
sudo passwd sakil
```

- পাসওয়ার্ড **হ্যাশ হয়ে** `/etc/shadow`-এ যায়
- টাইপ করার সময় **কিছুই দেখাবে না** — এটা স্বাভাবিক ✅

### ধাপ ৩: গ্রুপে যোগ করা

```bash
sudo usermod -aG developers sakil
```

> ⚠️ **সবচেয়ে গুরুত্বপূর্ণ সতর্কতা:**
> - `-a` = append (যোগ) — **এটা ভুললেই বিপদ!**
> - শুধু `-G` লিখলে আগের **সব সেকেন্ডারি গ্রুপ মুছে যায়**

```bash
groups sakil   # ভেরিফাই
```

### ধাপ ৪: প্রপার্টি পরিবর্তন

```bash
sudo usermod -l newname sakil              # নাম বদল (UID অপরিবর্তিত)
sudo usermod -d /home/newdir -m sakil      # হোম বদল (-m = ফাইল সরাও)
sudo usermod -s /bin/zsh sakil             # শেল বদল
sudo usermod -g developers sakil           # প্রাইমারি গ্রুপ বদল (ছোট -g)
```

### ধাপ ৫: লক / আনলক

```bash
sudo passwd -l sakil   # লক → shadow-তে হ্যাশের আগে '!' বসে
sudo passwd -u sakil   # আনলক
```

👉 ইউজার ডিলিট না করে সাময়িকভাবে বন্ধ করার সেরা উপায়।

### ধাপ ৬: এক্সপায়ার / ডিজেবল

```bash
sudo passwd -e sakil                # পরের লগইনে পাসওয়ার্ড বদলাতে বাধ্য
sudo chage -E 2026-12-31 sakil      # নির্দিষ্ট তারিখে অ্যাকাউন্ট বন্ধ
sudo chage -l sakil                 # এজিং তথ্য দেখা
```

### ধাপ ৭: ইউজার সুইচ (টেস্টিং)

```bash
su - sakil
```

- `-` (হাইফেন) → সম্পূর্ণ এনভায়রনমেন্ট লোড হয়
- হাইফেন ছাড়া `su sakil` দিলে PATH/হোম ঠিকমতো লোড হয় না — **কমন ভুল!**

### ধাপ ৮: ডিলিট

```bash
sudo userdel sakil       # হোম ডিরেক্টরি থেকে যায় ❌
sudo userdel -r sakil    # হোম + মেইল স্পুলসহ সম্পূর্ণ ক্লিনআপ ✅
```

> ⚠️ ডিলিটের আগে গুরুত্বপূর্ণ ফাইল **ব্যাকআপ** নিন!

## ৬. ইউজার পারমিশন (chmod, chown)

### পারমিশনের প্রকার

| পারমিশন | প্রতীক | সংখ্যা | ফাইলে  | ডিরেক্টরিতে |
| ------- | ------ | ------ | ------ | ----------- |
| Read    | r      | 4      | পড়া   | তালিকা দেখা |
| Write   | w      | 2      | এডিট   | তৈরি/ডিলিট  |
| Execute | x      | 1      | চালানো | প্রবেশ      |

### তিন ধরনের ব্যক্তি

- **u (User)** — মালিক
- **g (Group)** — গ্রুপ মেম্বার
- **o (Others)** — বাকি সবাই

### পারমিশন পড়া

```text
-rwxr-xr-- 1 rahim developers 1024 file.txt
│ └─┬─┘ └─┬─┘ └─┬─┘
│  owner group others
ফাইল
```

### chmod (Numeric)

```bash
chmod 755 file.txt     # rwxr-xr-x (স্ক্রিপ্টের জন্য)
chmod 644 file.txt     # rw-r--r-- (সাধারণ ফাইল)
chmod 600 file.txt     # rw------- (প্রাইভেট ফাইল, SSH key)
chmod -R 755 folder/   # রিকার্সিভ
```

### chmod (Symbolic)

```bash
chmod u+x script.sh    # মালিকের execute
chmod g-w file.txt     # গ্রুপের write বাদ
chmod o=r file.txt     # অন্যদের শুধু read
```

### chown (মালিকানা)

```bash
sudo chown rahim file.txt                  # মালিক বদল
sudo chown rahim:developers file.txt       # মালিক+গ্রুপ
sudo chgrp developers file.txt             # শুধু গ্রুপ
sudo chown -R rahim /path/                 # রিকার্সিভ
```

## ৭. একজন ইউজারকে sudo প্রিভিলেজ দেওয়া

```text
rahim ALL=(ALL:ALL) ALL
```

| অংশ         | মানে                      |
| ----------- | ------------------------- |
| `rahim`     | ইউজারনেম                  |

```text
rahim ALL=(ALL) NOPASSWD: /usr/bin/apt update
```

```bash
sudo -l -U rahim           # অনুমতি দেখা

```

## ৮. পাসওয়ার্ড এজিং ও chage কমান্ড

`/etc/shadow`-এর ফিল্ডগুলো ম্যানেজ করার সেরা টুল হলো `chage` — সরাসরি ফাইল এডিট করার দরকার নেই।

```bash
sudo chage -l rahim                  # সেটিংস দেখা
sudo chage -m 5 rahim                # Min days
sudo chage -M 90 rahim               # Max days
sudo chage -W 7 rahim                # সতর্কবার্তা
sudo chage -I 14 rahim               # Inactive
sudo chage -E 2024-12-31 rahim       # অ্যাকাউন্ট এক্সপায়ারি
sudo chage -E -1 rahim               # এক্সপায়ারি বাতিল
sudo chage -d 0 rahim                # প্রথম লগইনেই পাসওয়ার্ড বদলাতে বাধ্য ⭐
sudo chage -m 5 -M 90 -W 7 -I 14 rahim  # একসাথে সব
```

👉 **ব্যবহারিক টিপ:** নতুন ইউজার বানানোর পর `chage -d 0` দিন — প্রথমবার লগইন করে নিজের পাসওয়ার্ড সেট করতে বাধ্য হবে। কন্ট্রাক্ট কর্মী/ইন্টার্নদের জন্য `-E` দিয়ে মেয়াদ ঠিক করে দিন।

## ৯. su বনাম sudo

| বিষয়      | `su`       | `sudo`              |
| ---------- | ---------- | ------------------- |
| পাসওয়ার্ড | রুটের      | নিজের               |
| সুযোগ      | পুরো সেশন  | একটি কমান্ড         |
| লগ         | ট্রেস কঠিন | auth.log-এ রেকর্ড   |
| নিরাপত্তা  | কম         | বেশি (অডিট + সীমিত) |

### su ব্যবহার

```bash
su -           # রুট সেশন (সম্পূর্ণ পরিবেশসহ)
su - rahim     # রহিম হিসেবে সুইচ
```

> ⚠️ সবসময় `su -` (হাইফেন **সহ**) ব্যবহার করুন — হাইফেন ছাড়া দিলে এনভায়রনমেন্ট (PATH, HOME) ঠিকমতো লোড হয় না।

### sudo-এর দরকারি অপশন

```bash
sudo -i                # রুটের সম্পূর্ণ লগইন শেল
sudo -s                # রুট শেল
sudo -u rahim ls       # রহিম হিসেবে কমান্ড চালানো
sudo !!                # শেষ কমান্ডটি sudo সহ আবার চালানো ⭐
sudo -k                # টাইমস্ট্যাম্প রিসেট (পরেরবার আবার পাসওয়ার্ড লাগবে)
```

📌 sudo পাসওয়ার্ড ডিফল্টভাবে **১৫ মিনিট** মনে রাখে।

### 🏆 শ্রেষ্ঠ অভ্যাস (Best Practice)

- রুট লগইন বন্ধ রাখুন: `sudo passwd -l root`
- সরাসরি root ব্যবহার না করে সবাইকে **sudo** দিন — কে কখন কী করেছে তা `auth.log`-এ রেকর্ড হয় (অডিট ট্রেইল)

## ১০. বিশেষ পারমিশন বিট (SUID, SGID, Sticky Bit)

সাধারণ `rwx` পারমিশনের বাইরে আরও তিনটি **বিশেষ বিট** আছে:

```text
-rwsr-sr-t
│ │ └─ t = Sticky Bit
│ └──── s = SGID
└──────── s = SUID
```

### 🔴 SUID (4)

ফাইল চালালে চালানো ব্যক্তি **মালিকের (সাধারণত রুটের)** ক্ষমতা পায়।

```bash
ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root ... /usr/bin/passwd
```

👉 এ কারণেই সাধারণ ইউজার `passwd` কমান্ড চালিয়ে নিজের পাসওয়ার্ড বদলাতে পারে — অথচ `/etc/shadow` ফাইল তার পড়ারও অনুমতি নেই! কমান্ডটি চলার সময় **root-এর ক্ষমতায়** চলে।

```bash
chmod u+s file                 # বা chmod 4755 file
find / -perm -4000 -type f 2>/dev/null   # সিস্টেমের সব SUID ফাইল খোঁজা (অডিট)
```

### 🟡 SGID (2)

- **ফাইলে:** চালালে ফাইলের **গ্রুপের** ক্ষমতা পায়
- **ডিরেক্টরিতে:** ভেতরে তৈরি হওয়া **নতুন ফাইল অটোমেটিক সেই ডিরেক্টরির গ্রুপের হয়ে যায়** — টিম ফোল্ডারে দারুণ কাজে লাগে!

```bash
sudo groupadd developers
sudo mkdir /home/project
sudo chgrp developers /home/project
sudo chmod 2775 /home/project      # drwxrwsr-x
```

### 🔵 Sticky Bit (1)

ডিরেক্টরিতে থাকলে — যে ফাইল **নিজের, শুধু সে-ই সেটা ডিলিট করতে পারবে** (অন্যরা পড়তে/লিখতে পারলেও):

```bash
ls -ld /tmp
drwxrwxrwt 15 root root ... /tmp   # শেষে 't' দেখুন

chmod +t folder/                   # বা chmod 1777
```

### সারসংক্ষেপ

| বিট    | ফাইলে                | ডিরেক্টরিতে           | সংখ্যা | বাস্তব উদাহরণ     |
| ------ | -------------------- | --------------------- | ------ | ----------------- |
| SUID   | মালিকের ক্ষমতায় চলে | অর্থহীন               | 4      | `/usr/bin/passwd` |
| SGID   | গ্রুপের ক্ষমতায় চলে | গ্রুপ-উত্তরাধিকার     | 2      | টিম ফোল্ডার       |
| Sticky | অপ্রচলিত             | শুধু নিজের ফাইল ডিলিট | 1      | `/tmp`            |

### বড় হাতের বনাম ছোট হাতের অক্ষর (গুরুত্বপূর্ণ!)

- `rws` (ছোট s) → execute আছে, বিশেষ বিট **কার্যকর** ✅
- `rwS` (বড় S) → execute **নেই**, বিট **অকার্যকর** ⚠️
- `rwt` / `rwT` → Sticky Bit-এও একই নিয়ম

```bash
chmod 4754 file    # -rwsr-xr-- ✅ (কাজ করবে)
chmod 4644 file    # -rwSr--r-- ❌ (কাজ করবে না)
```

## ১১. রিয়েল-ওয়ার্ল্ড ওয়ার্কফ্লো ও কমন ভুল

### 🏢 প্রোডাকশন-রেডি ইউজার সেটআপ (সম্পূর্ণ উদাহরণ)

ধরুন, নতুন একজন ডেভেলপার "সাকিল" জয়েন করলো। আপনার করণীয়:

**ধাপ ১ — গ্রুপ তৈরি:**

```bash
sudo groupadd developers
```

**ধাপ ২ — ইউজার তৈরি (গ্রুপসহ একসাথে):**

```bash
sudo useradd -m -s /bin/bash -c "Sakil Mahmud" -G developers sakil
```

**ধাপ ৩ — পাসওয়ার্ড সেট + প্রথম লগইনে বদলাতে বাধ্য করা:**

```bash
sudo passwd sakil
sudo chage -d 0 sakil
```

**ধাপ ৪ — sudo অ্যাক্সেস দেওয়া:**

```bash
sudo usermod -aG sudo sakil
```

**ধাপ ৫ — টিম ফোল্ডারে অ্যাক্সেস দেওয়া (SGID ব্যবহার করে):**

```bash
sudo chmod 2775 /home/project
```

**ধাপ ৬ — সবকিছু ভেরিফাই:**

```bash
id sakil
sudo chage -l sakil
```

**ধাপ ৭ — টেস্ট করা:**

```bash
su - sakil
```

### 👤 ইউজার চলে গেলে (Offboarding)

```bash
sudo passwd -l sakil          # ১. প্রথমে লক করুন (ফাইল রেফারেন্স অটুট থাকে)
# দরকারি ফাইল ব্যাকআপ নিন...
sudo userdel -r sakil         # ২. তারপর সম্পূর্ণ ডিলিট
```

### ❌ কমন ভুলগুলো (অবশ্যই এড়াবেন)

| ❌ ভুল                                      | ফলাফল                                             | ✅ সমাধান                   |
| ------------------------------------------ | ------------------------------------------------- | -------------------------- |
| `useradd sakil` (`-m` ছাড়া)               | হোম ডিরেক্টরি নেই → লগইন সমস্যা                   | `useradd -m ...`           |
| `usermod -G developers sakil` (`-a` ছাড়া) | আগের সব গ্রুপ মুছে যায় (sudo হারাতে পারে!)       | `usermod -aG ...`          |
| `nano /etc/passwd` (ম্যানুয়াল এডিট)       | এক ক্যারেক্টার ভুলে সিস্টেম লগইন ভেঙে যেতে পারে   | সবসময় কমান্ড ব্যবহার করুন |
| `su sakil` (হাইফেন ছাড়া)                  | এনভায়রনমেন্ট লোড হয় না                          | `su - sakil`               |
| `nano /etc/sudoers` (সরাসরি এডিট)          | সিনট্যাক্স ভুলে sudo সম্পূর্ণ বন্ধ হয়ে যেতে পারে | `sudo visudo`              |

## ১২. Debian/Ubuntu-তে sudo সেটআপ (যদি sudo না থাকে)

আপনার `sudo` কমান্ডটি খুঁজে না পাওয়ার কারণ হলো, **Ubuntu-র বিপরীতে Debian-এ সাধারণত `sudo` প্যাকেজটি ডিফল্টভাবে ইনস্টল করা থাকে না**, বিশেষ করে যদি আপনি ইনস্টলেশনের সময় root পাসওয়ার্ড সেট করে থাকেন।

সমাধানের জন্য আপনাকে এখনও `root` হিসেবে আছেন, তাই সরাসরি নিচের ধাপগুলো অনুসরণ করতে পারবেন।

### 🛠️ ধাপ ১: `sudo` ইনস্টল করুন

root হিসেবে নিচের কমান্ডটি চালান:

```bash
apt update
apt install sudo -y
```

### 👤 ধাপ ২: আপনার ব্যবহারকারীকে `sudo` গ্রুপে যোগ করুন

আপনি এখনও root হিসেবে আছেন। `$LOGNAME` ভেরিয়েবলটি আপনার আসল ব্যবহারকারীর নাম ধারণ করে থাকে। নিচের কমান্ডটি চালালে আপনার অ্যাকাউন্টটি `sudo` গ্রুপে যুক্ত হবে:

```bash
adduser "$LOGNAME" sudo
```

**বিকল্প:** আপনি যদি সরাসরি ইউজারনেম দিতে চান (যেমন `adminuser`), তাহলে এই কমান্ডটি ব্যবহার করুন:

```bash
usermod -aG sudo আপনার_ইউজারনেম
```

### 🔄 ধাপ ৩: লগআউট ও পুনরায় লগইন করুন

গ্রুপ মেম্বারশিপের পরিবর্তন কার্যকর করতে **আপনাকে অবশ্যই লগআউট করে আবার লগইন করতে হবে**। root সেশন থেকে `exit` দিয়ে বেরিয়ে আসুন, তারপর আপনার সাধারণ ইউজার দিয়ে SSH করুন।

### ✅ ধাপ ৪: `sudo` কাজ করছে কিনা পরীক্ষা করুন

পুনরায় লগইন করার পর, আপনার সাধারণ ইউজার দিয়ে টেস্ট করুন:

```bash
sudo -l
```

এটি আপনার sudo权限ের তালিকা দেখাবে। এরপর `sudo whoami` চালিয়ে দেখুন, আউটপুটে `root` আসা উচিত।

### 💡 অতিরিক্ত টিপস

- **`su` vs `sudo`:** root পাসওয়ার্ড জানা থাকলে `su -` দিয়ে root হওয়া যায়। কিন্তু `sudo` ব্যবহার করা নিরাপদ, কারণ এটি কাজের লগ রাখে এবং গ্রানুলার permission দেওয়া যায়।
- **পাসওয়ার্ড:** `sudo` চালানোর সময় আপনার **নিজের ইউজার অ্যাকাউন্টের পাসওয়ার্ড** দিতে হবে, root পাসওয়ার্ড নয়।

এই ধাপগুলো শেষ হলে আপনি সফলভাবে `sudo` সেটআপ করে `PermitRootLogin no` করার পূর্বশর্ত পূরণ করতে পারবেন।

## ১৩. Root ইউজারের SSH অ্যাক্সেস বন্ধ করা (Debian/Ubuntu চেকলিস্ট)

Linux-এ root হিসেবে সরাসরি SSH লগইন বন্ধ করা অত্যন্ত গুরুত্বপূর্ণ নিরাপত্তা ব্যবস্থা। এর ফলে brute-force আক্রমণ থেকে root অ্যাকাউন্ট সুরক্ষিত থাকে এবং অ্যাডমিনরা sudo ব্যবহার করে কাজ করতে পারেন।

আপনি যেহেতু **Debian/Ubuntu** ব্যবহার করছেন, তাই কিছু বিষয় এই ডিস্ট্রোগুলোর জন্য বিশেষভাবে খেয়াল রাখা জরুরি:

- এখানে sudo গ্রুপের নাম `sudo` (RHEL-এর `wheel` নয়)
- SSH সার্ভিসের নাম `ssh` (`sshd` নয়)
- Ubuntu-তে root অ্যাকাউন্ট সাধারণত ডিফল্টভাবে লক করা থাকে

নিচে Debian/Ubuntu-এর জন্য ধাপে ধাপে **সম্পূর্ণ চেকলিস্ট** দিচ্ছি, যাতে `PermitRootLogin no` করার পরও আপনি অন্য ইউজার দিয়ে SSH করতে পারেন এবং প্রয়োজনে root权限 নিতে পারেন।

### ১. একটি sudo-সক্ষম ইউজার তৈরি ও টেস্ট

root বন্ধ করার আগে অবশ্যই একটি নন-রুট ইউজার থাকতে হবে, যে `sudo` চালাতে পারবে।

```bash
# নতুন ইউজার তৈরি (ইন্টারঅ্যাক্টিভ, পাসওয়ার্ড সেট করবে)
sudo adduser adminuser

# sudo গ্রুপে যোগ করুন (Debian/Ubuntu-তে এটাই সঠিক গ্রুপ)
sudo usermod -aG sudo adminuser

# গ্রুপ মেম্বারশিপ চেক
groups adminuser
# অথবা
id adminuser
```

> **মনে রাখবেন:** গ্রুপে যোগ করার পর ইউজারকে লগআউট/লগইন করতে হবে (বা নতুন SSH সেশন নিতে হবে) যাতে গ্রুপ মেম্বারশিপ কার্যকর হয়।

**টেস্ট করুন:**  
অন্য একটি টার্মিনাল থেকে `ssh adminuser@your_server` দিয়ে লগইন করুন। তারপর:

```bash
sudo -l          # sudo权限 দেখাবে
sudo whoami      # root দেখাবে
sudo -i          # root শেলে ঢুকবে
```

যদি এগুলো কাজ করে, তাহলেই আপনি root SSH বন্ধ করার জন্য প্রস্তুত।

### ২. SSH Key সেটআপ (যদি পাসওয়ার্ড অথেন্টিকেশন বন্ধ থাকে)

যদি আপনার সার্ভারে `PasswordAuthentication no` করা থাকে, তাহলে নতুন ইউজারের জন্য অবশ্যই SSH Key সেটআপ করতে হবে। নাহলে পাসওয়ার্ড দিয়ে লগইনই করতে পারবেন না।

**লোকাল মেশিন থেকে:**

```bash
# যদি না থাকে, কী জেনারেট করুন
ssh-keygen -t ed25519 -C "adminuser@server"

# পাবলিক কী সার্ভারে কপি করুন (পাসওয়ার্ড অথেন্টিকেশন চালু থাকলে)
ssh-copy-id adminuser@your_server
```

**যদি পাসওয়ার্ড অথেন্টিকেশন বন্ধ থাকে,** তাহলে ম্যানুয়ালি পাবলিক কী যোগ করুন:

```bash
# সার্ভারে adminuser হিসেবে লগইন করে (root দিয়ে অস্থায়ীভাবে)
sudo mkdir -p /home/adminuser/.ssh
sudo nano /home/adminuser/.ssh/authorized_keys
# আপনার পাবলিক কী পেস্ট করুন

sudo chown -R adminuser:adminuser /home/adminuser/.ssh
sudo chmod 700 /home/adminuser/.ssh
sudo chmod 600 /home/adminuser/.ssh/authorized_keys
```

### ৩. কনফিগ ব্যাকআপ ও ওভাররাইড চেক (Debian/Ubuntu-তে খুব গুরুত্বপূর্ণ)

Ubuntu 20.04+ এবং কিছু Debian ভার্সনে `/etc/ssh/sshd_config` ফাইলের ভিতরে `Include /etc/ssh/sshd_config.d/*.conf` থাকে। এর মানে হলো, `/etc/ssh/sshd_config.d/` ফোল্ডারের যেকোনো `.conf` ফাইল মূল কনফিগকে ওভাররাইড করতে পারে। ক্লাউড-ইনিট বা অন্যান্য টুল প্রায়ই এখানে `PermitRootLogin prohibit-password` সেট করে রাখে।

```bash
# ব্যাকআপ
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak

# সব জায়গায় PermitRootLogin খুঁজুন
sudo grep -Ri "PermitRootLogin" /etc/ssh/sshd_config /etc/ssh/sshd_config.d/
```

যদি `/etc/ssh/sshd_config.d/`-তে কোনো ফাইলে `PermitRootLogin` সেট করা থাকে, তাহলে সেটি এডিট করুন অথবা নতুন একটি ফাইল তৈরি করুন (যেমন `/etc/ssh/sshd_config.d/99-disable-root.conf`) যাতে নিচের লাইন থাকে:

```text
PermitRootLogin no
```

> **নোট:** `/etc/ssh/sshd_config`-এও `PermitRootLogin no` সেট করতে পারেন, তবে `.d` ফোল্ডারের ফাইলগুলো সাধারণত পরে পড়া হয়, তাই সেগুলোই কার্যকর হবে।

### ৪. সেশন খোলা রাখা ও কনসোল অ্যাক্সেস নিশ্চিত

- **বর্তমান root SSH সেশন বন্ধ করবেন না।** একটি দ্বিতীয় টার্মিনালে root হিসেবে SSH করে রাখুন।
- **VPS/Cloud Console** (VNC, Serial Console) অ্যাক্সেস আছে কিনা নিশ্চিত করুন। SSH-এ লকআউট হলে এটি দিয়েই উদ্ধার করা যাবে।

### ৫. `PermitRootLogin no` সেট করা ও রিস্টার্ট

```bash
# কনফিগ এডিট করুন
sudo nano /etc/ssh/sshd_config
# অথবা ওভাররাইড ফাইল
sudo nano /etc/ssh/sshd_config.d/99-disable-root.conf
```

লাইনটি যোগ/পরিবর্তন করুন:

```text
PermitRootLogin no
```

**সিনট্যাক্স চেক:**

```bash
sudo sshd -t
```

কোনো এরর না দিলে রিস্টার্ট করুন:

```bash
sudo systemctl restart ssh
# অথবা
sudo systemctl restart sshd
```

> Debian/Ubuntu-তে সার্ভিসের নাম সাধারণত `ssh`। `sshd` নামে অ্যালিয়াস থাকতে পারে, তবে `ssh` নিরাপদ।

**ভেরিফাই:**

```bash
sudo sshd -T | grep permitrootlogin
# আউটপুট: permitrootlogin no
```

### ৬. নতুন ইউজার দিয়ে টেস্ট

এখন **নতুন টার্মিনাল** খুলে (root সেশনটি খোলা রেখেই) চেষ্টা করুন:

```bash
ssh adminuser@your_server
```

লগইন সফল হলে:

```bash
sudo -i          # root শেল
# অথবা
sudo su -        # root শেল (sudo দিয়ে, তাই root পাসওয়ার্ড লাগবে না)
```

যদি সব ঠিকঠাক কাজ করে, তাহলে root SSH সেশনটি বন্ধ করতে পারেন।

**root SSH বন্ধ হয়েছে কিনা পরীক্ষা:**

```bash
ssh root@your_server
# Permission denied (publickey) বা similar মেসেজ আসবে
```

### ৭. লগআউট হলে কী করবেন

যদি কোনোভাবে লকআউট হয়ে যান:

1. VPS কনসোল / VNC দিয়ে ঢুকুন।
2. root হিসেবে লগইন করুন (কনসোলে root সাধারণত কাজ করে)।
3. `/etc/ssh/sshd_config` বা `/etc/ssh/sshd_config.d/`-এর ফাইল এডিট করে `PermitRootLogin yes` করে দিন।
4. `sudo systemctl restart ssh` দিন।
5. তারপর আবার SSH করে ঠিক করুন।

### ৮. Debian/Ubuntu-র জন্য বিশেষ টিপস

- **root পাসওয়ার্ড:** Ubuntu-তে root অ্যাকাউন্ট ডিফল্টভাবে লক থাকে (পাসওয়ার্ড নেই)। তাই `su -` কাজ করবে না, কিন্তু `sudo -i` কাজ করবে।
- **sudo গ্রুপ:** `usermod -aG sudo username` — এটাই সঠিক। `wheel` গ্রুপ Debian/Ubuntu-তে ডিফল্ট নয়।
- **লগ ফাইল:** `/var/log/auth.log` — SSH লগইন সফল/ব্যর্থতা দেখতে।
- **SSH কনফিগ টেস্ট:** `sudo sshd -t` এবং `sudo sshd -T`।
- **ফায়ারওয়াল:** যদি `ufw` ব্যবহার করেন, `sudo ufw allow ssh` নিশ্চিত করুন।
- **পাসওয়ার্ড অথেন্টিকেশন:** যদি `PasswordAuthentication no` করতে চান, তার আগে SSH Key টেস্ট করে নিন।

### সংক্ষেপে ক্রম (Debian/Ubuntu)

1. sudo ইউজার তৈরি + টেস্ট  
2. SSH Key সেটআপ (প্রয়োজনে)  
3. কনফিগ ব্যাকআপ + ওভাররাইড চেক  
4. root সেশন খোলা + কনসোল অ্যাক্সেস  
5. `PermitRootLogin no` সেট + `sshd -t` + রিস্টার্ট  
6. নতুন ইউজার দিয়ে SSH + `sudo -i` টেস্ট  
7. সব ঠিক থাকলে root সেশন বন্ধ

এই ধাপগুলো অনুসরণ করলে Debian/Ubuntu-তে নিরাপদে root SSH বন্ধ করতে পারবেন এবং নিজের sudo ইউজার দিয়েই root权限 পাবেন।

## ১৪. কোন কোন ইউজার SSH করতে পারবে তা নিয়ন্ত্রণ করা

ডিফল্টভাবে, সিস্টেমে থাকা **যেকোনো সক্রিয় ইউজার** SSH দিয়ে লগইন করতে পারে। অর্থাৎ root বন্ধ করলেও অন্য সব সাধারণ ইউজার SSH করতে পারবে। যদি আপনি শুধু নির্দিষ্ট ইউজারদের অনুমতি দিতে চান, তাহলে `AllowUsers` / `AllowGroups` ব্যবহার করতে হবে।

### AllowUsers (শুধু নির্দিষ্ট ইউজারদের অনুমতি)

```bash
sudo nano /etc/ssh/sshd_config
```

যোগ করুন:

```text
AllowUsers adminuser devuser
```

এটি শুধুমাত্র `adminuser` এবং `devuser`-কে SSH করতে দেবে; অন্য কেউ পারবে না। আপনি নির্দিষ্ট IP থেকেও সীমাবদ্ধ করতে পারেন:

```text
AllowUsers adminuser@192.168.1.100 devuser@10.0.0.*
```

### DenyUsers (নির্দিষ্ট ইউজার ব্লক করা)

```text
DenyUsers testuser tempuser
```

এটি সবাইকে অনুমতি দেবে `testuser` এবং `tempuser` ছাড়া।

### AllowGroups / DenyGroups (গ্রুপ ভিত্তিক নিয়ন্ত্রণ)

```text
AllowGroups sshusers
```

শুধুমাত্র `sshusers` গ্রুপের সদস্যরা SSH করতে পারবে।

### প্রসেসিং ক্রম

Allow/Deny ডিরেক্টিভগুলি নিম্নলিখিত ক্রমে প্রক্রিয়া করা হয়:

1. `DenyUsers`
2. `AllowUsers`
3. `DenyGroups`
4. `AllowGroups`

> ⚠️ `DenyUsers`-এ থাকা ইউজারের জন্য `AllowUsers` বিবেচনা করা হয় না; আবার `AllowUsers`-এ থাকা ইউজারকে `AllowGroups`-এর শর্তও পূরণ করতে হয়।

## ১৫. সব ইউজারের SSH বন্ধ করে শুধু নির্দিষ্টজনকে অনুমতি দেওয়ার কৌশল

সবচেয়ে কঠোর পদ্ধতি হলো **AllowUsers/AllowGroups** দিয়ে একটি whitelist তৈরি করা। যেমন:

```text
PermitRootLogin no
AllowUsers deploy admin
```

এর ফলে root ছাড়া শুধু `deploy` এবং `admin` ইউজারই SSH করতে পারবে। বাকি সব সক্রিয় ইউজার SSH করতে পারবে না।

### অতিরিক্ত নিরাপত্তা পরামর্শ

- **পাসওয়ার্ড অথেন্টিকেশন বন্ধ করে SSH কী ব্যবহার করুন:** `PasswordAuthentication no` সেট করুন।
- **ডিফল্ট পোর্ট পরিবর্তন:** `Port 2222` (যেকোনো নন-স্ট্যান্ডার্ড পোর্ট)।
- **Fail2Ban ইনস্টল করুন:** বারবার ভুল লগইন চেষ্টা করা IP স্বয়ংক্রিয়ভাবে ব্লক হবে।
- **sudo ইউজার তৈরি করুন:** root-এর পরিবর্তে `sudo` ব্যবহার করে অ্যাডমিন কাজ করুন।

### সংক্ষেপে SSH অ্যাক্সেস নিয়ন্ত্রণ

| লক্ষ্য                              | কনফিগারেশন               |
| ----------------------------------- | ------------------------ |
| root SSH বন্ধ                       | `PermitRootLogin no`     |
| শুধু নির্দিষ্ট ইউজার SSH করতে পারবে | `AllowUsers user1 user2` |
| নির্দিষ্ট ইউজার ব্লক                | `DenyUsers baduser`      |
| গ্রুপ ভিত্তিক অনুমতি                | `AllowGroups sshusers`   |

> **মনে রাখবেন:** যেকোনো পরিবর্তনের পর `sshd` রিস্টার্ট করতে ভুলবেন না এবং পরিবর্তন প্রয়োগের আগে একটি ব্যাকআপ SSH সেশন খোলা রাখুন, যাতে লকআউট হলে তা ঠিক করা যায়।

## ১৬. SSH এবং sshd: আসল কাহিনি

অনেকেই ভাবেন `ssh` আর `sshd` একই জিনিস, বা `sshd` হলো `ssh`-এর ডেমন সংস্করণ। আসলে বিষয়টা তা নয়। পরিষ্কারভাবে বললে:

- **SSH** = একটি **প্রোটোকল** (নিয়মকানুনের সেট), যার পুরো নাম **Secure Shell**। এটি দিয়ে নিরাপদে রিমোট মেশিনে লগইন, কমান্ড চালানো, ফাইল ট্রান্সফার, টানেলিং ইত্যাদি করা যায়।
- **OpenSSH** = SSH প্রোটোকলের সবচেয়ে জনপ্রিয় **বাস্তবায়ন** (implementation)। Linux, macOS, BSD-তে সাধারণত এটাই ব্যবহৃত হয়।
- **ssh** = OpenSSH স্যুটের **ক্লায়েন্ট প্রোগ্রাম**। আপনি যখন `ssh user@server` টাইপ করেন, তখন এই প্রোগ্রামটি চলে।
- **sshd** = OpenSSH স্যুটের **সার্ভার ডেমন** (daemon)। এটি ব্যাকগ্রাউন্ডে চলে, পোর্ট ২২-এ (বা অন্য পোর্টে) কান পেতে থাকে, এবং ক্লায়েন্টের কানেকশন গ্রহণ করে।

অর্থাৎ, `ssh` আর `sshd` হলো একই প্রোটোকলের **দুই প্রান্ত**। একটি ছাড়া অন্যটি অর্থহীন।  
`ssh` = কল করা পক্ষ (client), `sshd` = কল ধরার পক্ষ (server)।

### ssh বনাম sshd: পাশাপাশি তুলনা

| বিষয়        | ssh                                    | sshd                             |
| ------------ | -------------------------------------- | -------------------------------- |
| ধরন          | ক্লায়েন্ট প্রোগ্রাম                    | সার্ভার ডেমন                     |
| চলে          | ব্যবহারকারীর কমান্ডে, প্রয়োজন অনুযায়ী  | ব্যাকগ্রাউন্ডে, সবসময়            |
| পোর্ট        | রিমোট পোর্টে কানেক্ট করে               | নির্দিষ্ট পোর্টে listen করে      |
| কনফিগ        | `/etc/ssh/ssh_config`, `~/.ssh/config` | `/etc/ssh/sshd_config`           |
| কী           | ইউজার কী (`~/.ssh/id_*`)               | হোস্ট কী (`/etc/ssh/ssh_host_*`) |
| অথেন্টিকেশন  | সার্ভারকে যাচাই করে                    | ক্লায়েন্টকে যাচাই করে            |
| উদাহরণ       | `ssh user@host`                        | `systemctl start sshd`           |

### সাধারণ ভুল ধারণা

1. **"sshd হলো ssh-এর ডেমন সংস্করণ"** — না। `ssh` ক্লায়েন্ট, `sshd` সার্ভার। একই প্রোগ্রামের দুটি মোড নয়।
2. **"ssh ইনস্টল করলেই sshd ইনস্টল হয়"** — না। অনেক ডিস্ট্রোতে `openssh-client` আর `openssh-server` আলাদা প্যাকেজ।
3. **"ssh সার্ভিস মানে ssh"** — না। `systemctl start ssh` বা `sshd` মূলত `sshd` ডেমনকেই চালু করে।
4. **"root লগইন বন্ধ করলেই কেউ SSH করতে পারবে না"** — না। অন্য সব সক্রিয় ইউজার তখনও SSH করতে পারবে, যদি না `AllowUsers`/`AllowGroups` দিয়ে সীমাবদ্ধ করা হয়।

## ১৭. SSH প্রোটোকলের ভেতরের গল্প

SSH প্রোটোকল মূলত তিনটি স্তরে কাজ করে:

1. **Transport Layer**
   - এনক্রিপশন, ইন্টিগ্রিটি, হোস্ট অথেন্টিকেশন।
   - কী এক্সচেঞ্জ (Key Exchange) হয়ে সেশন কী তৈরি হয়।
   - সার্ভার তার **হোস্ট কী** দিয়ে নিজের পরিচয় প্রমাণ করে।

2. **User Authentication Layer**
   - ক্লায়েন্ট নিজের পরিচয় প্রমাণ করে।
   - পাসওয়ার্ড, পাবলিক কী, কীবোর্ড-ইন্টারেক্টিভ, OTP ইত্যাদি।

3. **Connection Layer**
   - একাধিক লজিক্যাল চ্যানেল তৈরি হয়।
   - শেল সেশন, পোর্ট ফরওয়ার্ডিং, X11 ফরওয়ার্ডিং, SFTP ইত্যাদি।

এই তিন স্তর একসাথে কাজ করে বলেই SSH নিরাপদ ও শক্তিশালী।

## ১৮. ssh (ক্লায়েন্ট) কী করে?

`ssh` একটি ক্লায়েন্ট প্রোগ্রাম। এর কাজ:

- TCP কানেকশন খোলে (ডিফল্ট পোর্ট ২২)।
- সার্ভারের হোস্ট কী যাচাই করে (`~/.ssh/known_hosts` ফাইলের সাথে মিলিয়ে)।
- কী এক্সচেঞ্জ করে এনক্রিপ্টেড চ্যানেল তৈরি করে।
- ব্যবহারকারীর পরিচয় প্রমাণ করে (পাসওয়ার্ড বা SSH কী)।
- এরপর:
  - রিমোট শেল চালায় (`ssh user@host`)
  - একক কমান্ড চালায় (`ssh user@host "ls -l"`)
  - পোর্ট ফরওয়ার্ড করে (`ssh -L`, `ssh -R`, `ssh -D`)
  - X11 ফরওয়ার্ড করে (`ssh -X`)
  - `scp`, `sftp`-এর ভিতরেও `ssh` ব্যবহৃত হয়।

`ssh` তার কনফিগ পড়ে:
- `/etc/ssh/ssh_config` (সিস্টেম-ওয়াইড)
- `~/.ssh/config` (ব্যবহারকারী-নির্দিষ্ট)

উদাহরণ:

```bash
ssh -p 2222 user@192.168.1.10
ssh -i ~/.ssh/mykey user@server
ssh -v user@server               # ডিবাগ মোড
```

## ১৯. sshd (সার্ভার ডেমন) কী করে?

`sshd` হলো সার্ভার-সাইড ডেমন। এটি:

- ব্যাকগ্রাউন্ডে চলে, নির্দিষ্ট পোর্টে (ডিফল্ট ২২) listen করে।
- নতুন কানেকশন এলে একটি চাইল্ড প্রসেস তৈরি করে তা হ্যান্ডেল করে।
- হোস্ট কী ব্যবহার করে নিজের পরিচয় প্রমাণ করে।
- ক্লায়েন্টের অথেন্টিকেশন যাচাই করে।
- সেশন, পোর্ট ফরওয়ার্ডিং, SFTP সাবসিস্টেম ইত্যাদি পরিবেশন করে।

`sshd` তার কনফিগ পড়ে:
- `/etc/ssh/sshd_config`

`sshd`-এর গুরুত্বপূর্ণ ফাইল:
- হোস্ট কী: `/etc/ssh/ssh_host_rsa_key`, `ssh_host_ed25519_key` ইত্যাদি
- ইউজার কী: `~/.ssh/authorized_keys`
- লগ: `/var/log/auth.log` (Debian/Ubuntu) বা `/var/log/secure` (RHEL/CentOS)

`sshd` সাধারণত systemd সার্ভিস হিসেবে চলে:

```bash
sudo systemctl start sshd      # RHEL/CentOS/Fedora
sudo systemctl start ssh       # Debian/Ubuntu (ssh.service মানে sshd)
sudo systemctl status sshd
```

ডিবাগ করার জন্য সরাসরি চালানো যায়:

```bash
sudo /usr/sbin/sshd -d -p 2222
```

### sshd-এর প্রসেস মডেল ও প্রিভিলেজ সেপারেশন

`sshd` যখন চলে, তখন একটি **মাস্টার প্রসেস** root হিসেবে পোর্ট ২২-এ listen করে। নতুন কানেকশন এলে:

1. মাস্টার প্রসেস একটি চাইল্ড প্রসেস fork করে।
2. চাইল্ড প্রসেসটি প্রথমে root হিসেবে কিছু কাজ করে (যেমন ইউজার সুইচ)।
3. তারপর **privilege separation**-এর মাধ্যমে একটি আনপ্রিভিলেজড চাইল্ড ও একটি মনিটর প্রসেস তৈরি হয়।
4. মনিটর প্রসেস root থাকে, কিন্তু আসল কাজ করে আনপ্রিভিলেজড চাইল্ড।

এই ডিজাইনের কারণে `sshd`-এ কোনো দুর্বলতা থাকলেও আক্রমণকারী সরাসরি root পায় না। এটাই OpenSSH-এর অন্যতম বড় নিরাপত্তা বৈশিষ্ট্য।

## ২০. হোস্ট কী বনাম ইউজার কী

SSH-এ দুই ধরনের কী থাকে:

1. **হোস্ট কী (Host Key)**
   - সার্ভারের নিজের পরিচয়।
   - `/etc/ssh/ssh_host_*` ফাইলে থাকে।
   - ক্লায়েন্ট প্রথমবার কানেক্ট করলে এই কী দেখে, `known_hosts`-এ সেভ করে।
   - পরবর্তীতে কী বদলে গেলে সতর্কবার্তা দেয় (MITM আক্রমণের সম্ভাবনা)।

2. **ইউজার কী (User Key)**
   - ব্যবহারকারীর পরিচয়।
   - `~/.ssh/id_rsa`, `id_ed25519` ইত্যাদি প্রাইভেট কী।
   - পাবলিক কী সার্ভারের `~/.ssh/authorized_keys`-এ রাখতে হয়।
   - পাসওয়ার্ডের চেয়ে নিরাপদ ও সুবিধাজনক।

`ssh-keygen` দিয়ে কী তৈরি হয়। `ssh-copy-id` দিয়ে পাবলিক কী সার্ভারে কপি করা যায়।

## ২১. SSH অথেন্টিকেশন পদ্ধতি ও টানেলিং

### অথেন্টিকেশন পদ্ধতি

`sshd` বিভিন্ন পদ্ধতিতে ইউজার যাচাই করতে পারে:

- **PasswordAuthentication** - সাধারণ পাসওয়ার্ড।
- **PubkeyAuthentication** - SSH কী।
- **KeyboardInteractive** - OTP, 2FA ইত্যাদি।
- **HostbasedAuthentication** - হোস্ট ভিত্তিক (কম ব্যবহৃত)।
- **GSSAPI** - Kerberos ইত্যাদি।

নিরাপত্তার জন্য পাসওয়ার্ড বন্ধ করে শুধু পাবলিক কী চালু করা উত্তম:

```text
PasswordAuthentication no
PubkeyAuthentication yes
```

### SSH টানেলিং

`ssh` শুধু লগইনের জন্য নয়। এটি একটি পূর্ণ টানেলিং টুল:

- **লোকাল ফরওয়ার্ড:** `ssh -L 8080:localhost:80 user@server`
- **রিমোট ফরওয়ার্ড:** `ssh -R 9090:localhost:3000 user@server`
- **ডাইনামিক ফরওয়ার্ড (SOCKS proxy):** `ssh -D 1080 user@server`
- **X11 ফরওয়ার্ড:** `ssh -X user@server`

এসব ক্ষেত্রে `sshd` সার্ভার প্রান্তে টানেলের শেষ পয়েন্ট হিসেবে কাজ করে।

## ২২. অধ্যায় সারসংক্ষেপ ও গোল্ডেন রুল

### 📝 এক নজরে পুরো বিষয়

```text
ইউজার তৈরি     → useradd -m, passwd, userdel -r
গ্রুপ           → groupadd, groupdel, usermod -aG
তথ্য ফাইল       → /etc/passwd, /etc/shadow, /etc/group, /etc/gshadow
ডিফল্ট সেটিংস  → /etc/default/useradd, /etc/login.defs, /etc/skel
পারমিশন        → chmod (755, 644, 600), chown, chgrp
অ্যাডমিন        → sudo, visudo, usermod -aG sudo
নিরাপত্তা       → chage, passwd -l/-u/-e, find -perm -4000
বিশেষ বিট      → SUID(4), SGID(2), Sticky(1)
SSH নিয়ন্ত্রণ → PermitRootLogin no, AllowUsers, AllowGroups
```

### 🧠 মেন্টাল মডেল (মনে রাখার সহজ উপায়)

যখন আপনি `useradd + passwd + usermod` চালান আপনি আসলে পরোক্ষভাবে **তিনটি ফাইল মডিফাই করছেন**:

| ফাইল          | কী যোগ/বদলায়                  |
| ------------- | ------------------------------ |
| `/etc/passwd` | ইউজারনেম, UID, GID, হোম, শেল   |
| `/etc/shadow` | পাসওয়ার্ড হ্যাশ, এজিং         |
| `/etc/group`  | গ্রুপ মেম্বারশিপ               |

### 📌 অধ্যায়ের ৫টি গোল্ডেন রুল

1. ইউজার তৈরিতে সবসময় `-m -s /bin/bash` ব্যবহার করুন
2. গ্রুপে যোগে সবসময় `-aG` (কখনোই শুধু `-G` নয়!)
3. কনফিগ ফাইল ম্যানুয়ালি এডিট নয় — কমান্ড ব্যবহার করুন
4. sudoers এডিট করতে **শুধু** `visudo`
5. root দিয়ে কাজ নয় — sudo দিয়ে কাজ করুন (অডিট ট্রেইল থাকে)

### অতিরিক্ত SSH গোল্ডেন রুল (Debian/Ubuntu)

6. root SSH লগইন সবসময় বন্ধ রাখুন (`PermitRootLogin no`)
7. পরিবর্তনের আগে ব্যাকআপ SSH সেশন খোলা রাখুন
8. সম্ভব হলে পাসওয়ার্ড অথেন্টিকেশন বন্ধ করে SSH কী ব্যবহার করুন
9. `/etc/ssh/sshd_config.d/` ফোল্ডারের ওভাররাইড ফাইলগুলো অবশ্যই চেক করুন
10. Debian-এ sudo না থাকলে প্রথমে `apt install sudo` করুন
